# monthly-accounting-report

小企业会计准则月度报表自动编制。

读取**上月的会计报表**和**本月的银行对账单、业务单据**，自动算出本月的五张报表：
资产负债表、利润表、现金流量表、利润表季报、现金流量表季报。输出 xlsx，版式与
财务软件导出的报表一致。

---

## 设计思路

### 一、以会计分录为唯一枢纽

最直觉的做法是照着报表逐格去算：货币资金怎么来、应付账款怎么来、营业成本怎么来。
这条路能走通，但三张表各算各的，勾稽关系全靠人工维护——改了一处忘了另一处，
表就不平了，而且不平的时候你不知道错在哪。

这个程序中间加了一层**分录**：

```
银行对账单 ─┐
业务回单   ─┼─→ 会计分录（借贷平衡） ─┬─→ 资产负债表
业务事项表 ─┘                        ├─→ 利润表
                                     └─→ 现金流量表
```

所有输入先转成借贷分录，三张表都从**同一批分录**派生。这样：

- 资产负债表平衡是**结构性成立**的（每笔分录借贷相等，损益类科目结转进未分配利润）
- 现金流量表与货币资金的勾稽自动成立（现金流就是分录里现金科目那一侧）
- 利润表与未分配利润的勾稽自动成立

不需要额外去"凑"，也就没有凑错的机会。

### 二、按列的性质分开取数

这是最容易写错的地方。报表里的数字只有两类：

- **存量**（时点余额，如货币资金）—— 像水位，`今天水位 = 昨天水位 + 今天进水`
- **流量**（期间发生额，如本月营业成本）—— 像今天的进水量，**跟昨天进了多少水毫无关系**

把"上期 + 本期变动"这个句式套到流量列上，就会算出 `600 + 115 = 115` 这种等号两边
量纲不一致的东西。本项目严格分开：

| 列 | 取数规则 |
|---|---|
| 资产负债表·期末余额 | 期初余额 + 本期发生额 |
| 利润表 / 现金流量表·**本月** | 本期发生额直接汇总（**与上月本月值无关**） |
| 利润表 / 现金流量表·本年累计 | 上月累计 + 本月 |
| 季报·本季度 | 上月同季度值 + 本月（跨季度重新起算） |

合计行一律由公式重算，不从上期继承，避免上期的舍入误差滚雪球。

现金流量表季报的"期初现金余额"是**存量不是流量**，所以单独处理：本季期初 =
本季首月的期初，而不是各月期初相加。

### 三、金额全程 Decimal

`0.1 + 0.2` 用 float 会得到 `0.30000000000000004`。会计报表要求元至角分，
差一分就是错。全部用 `Decimal` 量化到分，只在写 xlsx 时转 float。

### 四、匹配不上就报错，绝不静默入账

三种情况会中止出表并列出问题清单：

- 银行流水的摘要找不到科目映射
- 业务事项表里写了未定义的科目
- 勾稽关系不成立

**宁可不出表，也不出一张看着像样、实际不平的表。** 报错信息会直接说明改哪个文件、
加什么内容——对不写代码的使用者来说，报错信息就是说明书。

### 五、PDF 用坐标解析，不用文本流

财务软件导出的资产负债表是左右两栏，PyMuPDF 按行读文本会把两栏串在一起
（`99,368.42   短期借款`）。本项目改用词坐标：按 y 聚成视觉行，用表头位置确定列中心，
以 1~53 的行次整数作为行锚点，数值按中心距就近归列。

数值一律是两位小数、行次是 1~2 位整数，用正则就能干净分开，不必靠位置猜。
解析完还会校验行次集合完整，缺行直接报错。

## 使用方法

### 安装

需要 Python 3.10+。

```bash
pip install -r requirements.txt
```

### 初始化（首次）

```bash
python -m accounting_report --init
```

会建好 `输入/`、`输出/` 目录和一张空的 `业务事项.xlsx`。

### 每月出表

**第 1 步**，把这些放进 `输入/`：

| 放什么 | 说明 | 必需 |
|---|---|---|
| 本月银行对账单 PDF | 网银导出，流水的主数据源 | 是 |
| 本月业务回单 PDF | 用于交叉校验，可多份 | 否 |
| `业务事项.xlsx` | 不走银行的业务，见下 | 视情况 |
| 上月 5 表 PDF | 财务软件导出 | **仅首月** |

从第二个月起，程序会自动读 `输出/` 里上月生成的 xlsx 接续取数，不用再导 PDF。

**第 2 步**，填 `业务事项.xlsx`。银行对账单只能反映"钱动了"的业务；挂账费用、
计提折旧、应收应付这些**不动钱**的业务，对账单里一个字都没有，必须在这里填：

| 日期 | 摘要 | 借方科目 | 贷方科目 | 金额 | 来源 |
|---|---|---|---|---|---|
| 2026-06-30 | 本月云服务费（未结算） | 营业成本 | 应付账款 | 1000.00 | 供应商账单 |
| 2026-06-30 | 计提折旧 | 管理费用 | 累计折旧 | 500.00 | 折旧表 |

科目名必须在 `accounting_report/rules/accounts.yaml` 里定义过，写错会报错并提示。

**第 3 步**，出表：

```bash
python -m accounting_report --month 2026-06
```

Windows 用户也可以直接双击 `运行.bat`，它会问你月份。

输出在 `输出/2026-06 会计报表.xlsx`。

### 税务申报底稿（输出 5/6/7）

除三张报表外，引擎还会自动生成税务底稿、记账凭证与试算平衡表：**增值税申报底稿、企业所得税预缴底稿、个税扣缴明细表、记账凭证、试算平衡表**。

| 底稿 | 数据来源 | 说明 |
|---|---|---|
| 增值税申报底稿 | 发票 PDF（自动识别）或 `输入/企业信息/发票台账.xlsx` | 9/9 电子发票自动识别号码/购方/销方/金额/税额；**进项（购方=本公司）不计入销售额**，方向未识别归「待确认」 |
| 企业所得税预缴底稿 | 利润表累计数 + `输入/企业信息/资产台账.xlsx` + `输入/企业信息/员工名册.xlsx` | 自动判定小微企业（利润 ≤300 万 / 资产 ≤5000 万 / 人数 ≤300），税负 5% |
| 个税扣缴明细表 | `输入/{年}-{月}/工资社保/工资表.xlsx` | 员工维度累计预扣预缴 + 专项附加扣除汇总 |
| 记账凭证 | 分录自动生成 | 按(日期,摘要)分组 → 记字N号，含凭证小计/合计与制证人/审核人 |
| 试算平衡表 | 分录 + 上月报表 | 借贷必平校验（期初/本期/期末） |

以上数据源缺失时，对应底稿输出文件名带 `[模板]` 前缀并标注缺失项；
补齐后自动升级为正式输出。示例数据可用工具生成：

```bash
python tools/generate_ledger_samples.py   # 生成资产台账/员工名册/工资表示例
```

### 运行结果

```
本月分录 3 笔：
  2026-06-05  借 货币资金 / 贷 营业收入      5000.00   客户货款
  2026-06-20  借 管理费用 / 贷 货币资金       800.00   办公费
  2026-06-30  借 营业成本 / 贷 应付账款      1000.00   云服务费（未结算）

单据核对：
  回单核对通过：2026-06-05 客户货款 5000.00

勾稽校验：
  ✓ 分录借贷平衡（3 笔）
  ✓ 资产负债表平衡
  ✓ 未分配利润勾稽
  ✓ 现金流量表与货币资金勾稽
  ✓ 季报与月报衔接（第 2 季度）
```

**"本月分录"那几行要逐笔看一眼**——这是程序对本月业务的理解。

## 出错怎么办

### 「以下银行流水无法归类到科目」

最常见。说明有笔流水程序没见过：

```
以下银行流水无法归类到科目，请在 accounting_report/rules/mapping.yaml
补充 bank_rules 后重跑：
  2026-06-10  某某科技货款  对方:某某科技有限公司  借0 贷5000.00
```

打开 `accounting_report/rules/mapping.yaml`，照已有格式加一条：

```yaml
  - match: 某某科技
    account: 营业收入
    note: 客户货款
```

`match` 是关键词（在摘要和对方户名里查找），`account` 是对应科目。加一次永久有效。

### 「未定义的科目」

业务事项表里科目名写错了。正确的科目名见 `accounting_report/rules/accounts.yaml`。

### 「勾稽校验未通过」

程序算出来的表不平，这是它在拦截错误结果。**别手工改 xlsx 凑数**，把完整提示发给开发。

## 目录结构

```
accounting_report/
├── cli.py / pipeline.py      入口与端到端流程
├── models.py                 Account / JournalEntry / PriorPeriod / ReportSet
├── rules/                    规则文件（改这里不用改代码）
│   ├── accounts.yaml           科目表：报表行次归属 + 现金流分类
│   ├── balance_sheet.yaml      三张表的合计公式
│   ├── income_statement.yaml
│   ├── cash_flow.yaml
│   ├── mapping.yaml            银行摘要 → 科目
│   └── layout.yaml             行次 ↔ 单元格坐标（自动生成，勿手改）
├── parsers/                  上月报表 PDF/xlsx、对账单、回单、业务事项、票据CSV
├── engine/                   分录 → 发生额 → 三表 → 季报 → 勾稽校验
├── writers/xlsx_writer.py    按模板填数
└── templates/报表模板.xlsx   版式蓝本（空白，只有表头和科目行）
tools/build_template.py       从样表重新生成模板与 layout.yaml
tests/                        测试
```

## 测试

```bash
python -m pytest tests/ -v
```

- `test_engine.py` —— 引擎核心逻辑，全部使用**虚构数字**，覆盖存量/流量/累计/季报/
  跨季重算/跨年清零/勾稽拦截
- `test_error_paths.py` —— 失败路径，锁定报错信息的内容（对使用者来说报错就是说明书，
  不能在重构时被改烂）
- `test_regression_202605.py` —— 真实账套的逐格回归比对。**真实数据不在版本库里**，
  没有数据时本组自动跳过

> 真实账套数据（银行账号、回单验证码、公司财务状况）不进版本库。
> 回归基线在开发者本地维护：用上月输入算本月，与人工编制的成品逐单元格比对
> （1000+ 格），任一格不等即失败。

## 扩展

**新增科目**：编辑 `rules/accounts.yaml`，填 `bs` / `is` 行次和 `cf_in` / `cf_out`
现金流归类，不用改代码。

**新的银行摘要**：编辑 `rules/mapping.yaml` 的 `bank_rules`。

**换银行**：新写一个 `parsers/xxx_statement.py`，产出 `BankTxn` 列表即可，
下游不用动。

**报表版式变了**：把新样表放到项目根目录，改 `tools/build_template.py` 里的
`SAMPLE` 路径后运行它，模板和 `layout.yaml` 会重新生成。

## 已知限制

- 银行对账单解析目前只实现了工商银行企业网银导出的版式
- 票据 OCR（`票据记录.csv`）的接口已实现，尚未用真实 OCR 输出验证
- 发票购方识别依赖电子发票 PDF 的文本层；扫描件（图片型 PDF）暂不支持
